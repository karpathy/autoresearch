Local research memory for labs and agents

ResearchFS documentation

ResearchFS is a local SQLite-backed research memory layer that ingests papers, notes, PDFs, arXiv source text, repository READMEs, and experiment reports; compresses them into method/provenance memory; retrieves bounded context; and logs experiments, feedback, token usage, and lessons.

Storage

Local-first

Research artifacts, compressed memory, feedback, and experiment logs live in a local SQLite database by default.

Compression

Compressed memory

Chunks preserve source provenance while optional extraction turns artifacts into method records with implementation hints and risks.

Retrieval

Bounded retrieval

Method packs, graph context, and paper memory cards are assembled with local keyword matching and character budgets.

Audit

Auditable experiments

Retrieval events, feedback, outcomes, token usage, and lessons are persisted so later runs can inspect what happened.

ResearchFS is local-only by default; keep the stdlib API bound to loopback such as 127.0.0.1 because it has no built-in authentication.

Quick start

Python 3.10+ and uv; researchfs-core has only requests and pypdf as runtime dependencies.

Optional extraction uses uv sync --extra llm, requires OPENAI_API_KEY, and can run with uv run python -m researchfs.ingest --file notes/clip-matrix.md --extract.

The default SQLite file is researchfs.db; RESEARCHFS_DB_PATH overrides it.

uv sync
uv run python -m researchfs.ingest --file notes/clip-matrix.md
uv run python -m researchfs.memory query --query "clip matrix optimizer risk" --max-chars 3000

Ingestion sources

ResearchFS ingests local research artifacts and stores source labels for corpus inspection and retrieval provenance.

  • .txt files
  • .md files
  • .markdown files
  • .tex files
  • .pdf files
  • arXiv source text
  • repository README
  • in-process metadata dictionary

Exact source_type examples: paper, lab_note, experiment_report, repo_readme, and file.

uv run python -m researchfs.ingest --arxiv 2305.13245
uv run python -m researchfs.ingest --repo https://github.com/example/project
uv run python -m researchfs.ingest --file notes/clip-matrix.md --source-type lab_note

Retrieval and memory modes

method mode returns the bounded method/provenance/lesson pack for an agent prompt. graph mode returns graph context. memory mode returns bounded paper memory cards through the research brief implementation.

/brief and mode="memory" use deterministic local SQLite/stdlib keyword assembly over compressed markdown memory, with no fresh LLM call, no raw full-paper context, no vector search, no OCR, and no hosted search service.

uv run python -m researchfs.memory query --query "optimizer risk" --source-type paper --source-type lab_note --max-chars 3000 --include-scores --log
uv run python -m researchfs.memory export --paper-id 42 --output paper-42.bundle.json
uv run python -m researchfs.memory import --db-path /tmp/target.db --input paper-42.bundle.json

from researchfs import ResearchFSLabClient

client = ResearchFSLabClient()
brief = client.research_brief(
    query="clip matrix optimizer risk",
    max_chars=3000,
    max_papers=2,
    source_types=["paper", "lab_note"],
    include_scores=True,
    log=True,
)
print(brief["context"])

Context routing

Route a bounded selected evidence frontier before passing context to a reader; rejected candidates remain audit-only and can guide retry/recovery.

Deterministic routed ask defaults do not require provider SDKs, model packages, or GPU.

uv run python -m researchfs.memory ask --query "clip matrix optimizer risk" --route-context --verify --recover --max-papers 3 --k 2 --max-reader-tokens 1200 --log
from researchfs.context import ContextBudget, route_top_k_context

selection = route_top_k_context(
    candidates,
    k=2,
    budget=ContextBudget(max_items=2, max_tokens=800, overflow_policy="drop_lowest_score"),
)
answer = reader(question, context=selection.selected)

Benchmarks and evaluation fixtures

NanoChat/autoresearch is a separately managed project under benchmarks/nanochat; Torch, Modal, training code, and benchmark images are excluded from researchfs-core.

The current CLI supports one --distractor-mode per scaling run; available modes are mixed, closer_gold_like, near_miss_citation, partial_evidence, and conflicting_evidence.

PaperServe-Bench is local, synthetic, dependency-free, and does not download/run AutoResearchBench or claim official external benchmark scores.

uv run python -m examples.paperserve_benchmark --compact
uv run python -m examples.paperserve_benchmark --scaling --table --corpus-sizes 5,20,50,100
uv run python -m examples.paperserve_benchmark --compact --scaling --corpus-sizes 5,20,50,100 --distractor-mode conflicting_evidence --check-thresholds --output paperserve-scaling-conflicting.json --csv-output paperserve-scaling-conflicting.csv
cd benchmarks/nanochat
uv sync
uv run python compare_runs.py --list

Development checks

uv run pytest tests/test_regressions.py -q
